## Test corrections after the RED run (documented in the test headers)
1. **tDataTables/griddedInterpolantIndep: failed hypothesis H4.** The registered 1e-12 ABSOLUTE agreement with griddedInterpolant on all 21 tables failed on the three thrust tables by 7.3e-12 lb at |T| about 28,880 lb. That is 2 ulp: eps(28880) = 3.6e-12, so the bound is below double resolution there. The registered check is KEPT on the 18 aero tables (measured 8.3e-17). A corrected check, 1e-12 times each table's largest |value| on all 21 tables, was added with an independent justification (rounding of a d-linear interpolation is a few ulp of the scale; measured 4.3e-16). The aero tolerance was not loosened.
2. **tDataPerformance: measurement order.** The first GREEN run measured 1.069, with batches always ordered 0.9.1-CORE then fromData, while another agent's suite loaded the machine. Under the same conditions, the frozen model timed against a second copy of itself gave 1.027, the same as fromData against it (1.025), so the excess was order and load noise. The order now alternates in each batch pair, 15 pairs are used, and the same-code ratio is reported as a noise floor. The 1.05 bound and the ratio of medians are unchanged.
3. **tDataInventory/everyItemHasUnitsAndSource and tDataValidate/noUnitsIsError (additions after GREEN, stricter):** every item's units string must be known to `vital.data.unitFactor`, and an unknown unit raises `vital:data:unknownUnits` (FC-1079).
4. **tDataJson/loadErrors (an addition after the first sabotage run, stricter).** SD-9, which bypasses the expression name whitelist, was NOT DETECTED at first. The test's only malicious expression, `system('dir')`, is also refused by the second, character-level check because of its quotes. A quote-free disallowed call, `fprintf(v_CL_alpha)`, was added; it reaches the name check only. SD-9 is now DETECTED, and tests/M9/data is 32/32 again.
